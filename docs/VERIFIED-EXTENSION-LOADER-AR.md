# تحميل حزم المصادر الموقعة — 23 أكتوبر 2026

## التنفيذ

أضيف `ExtensionLoader` إلى `runtime-host` لربط فاحص توقيع JAR بسجل
`SourceRegistry`. الوحدة خارج هدف تطبيق iOS الرئيسي؛ الإضافة المنشورة لم
تُشغّل بهذا المسار بعد.

المدخلات المطلوبة: SHA-256 للملف، وبصمة DER لشهادة موثوقة يختارها المضيف،
وهوية الحزمة والإصدار وصنف التشغيل ومعرّفات المصادر ولغاتها.
تطابق شهادة المستودع ليس تأسيسًا مستقلًا لثقة الناشر.

1. تُنسخ الحزمة بحدود الحجم إلى ملف 0600 داخل مجلد خاص 0700.
2. تُفحص بنية ZIP وتُفتح JarFile، ثم يُحذف اسم الملف والمجلد قبل إعادة
   التحقق من توقيعات جميع الحمولات. يبقى المقبض نفسه مفتوحًا.
3. يقرأ محمّل الأصناف والموارد من ذلك المقبض؛ استبدال مسار الملف الأصلي
   بعد الفحص لا يغيّر محتواه. لا تُستخدم URLClassLoader أو إعادة فتح المسار.
4. تُطابق AndroidManifest النصية من الأرشيف ذاته مع metadata المتوقعة؛
   تُرفض الكيانات الخارجية وDOCTYPE والمدخلات المتجاوزة للحدود.
5. يجب أن ينتمي الصنف للأرشيف، ويكون عامًا وغير مجرد وله constructor عام
   دون معاملات، ويطبق Source أو SourceFactory. تُفحص هذه الشروط قبل التهيئة.
6. ينتقل المقبض إلى سجل المصادر عند التسجيل. الإزالة تمنع طلبات جديدة
   وتلغي العمليات القائمة، ثم تغلق الأرشيف بعد اكتمال تنظيفها.

يُستخدم محمّل الحزمة كسياق الخيط أثناء التهيئة وcreateSources وطلبات المصدر،
مع استعادته عند مغادرة السياق وعبر تعليق coroutines واستئنافها.

## الموارد والتوافق

- تُحفظ CodeSigner مع الأصناف، وبيانات package وsealing.
- اختيار multi-release يراعي نسخة JVM مع التحقق من جميع المدخلات الفيزيائية.
- روابط الموارد خاصة بالمقبض ومشفرة للمسافات والعربية وemoji و# و%؛ لا
  تفتح اسم ملف ولا عنوان شبكة، ومقارنات هويتها لا تستعلم DNS.
- يُرفض تضمين أصناف تحجب واجهات المضيف، وكذلك Class-Path خارجي في manifest؛
  التبعيات المطلوبة تُوفّر صراحة في المضيف.
- يتطلب هذا التنفيذ POSIX وحذف ملف مفتوح؛ فشل ذلك يرفض التحميل. إثباته
  على Linux لا يثبت عمل JarFile أو XML أو محمّل الأصناف على iOS.
- عقد المكتبة المقبول حاليًا هو 1.6؛ توافق الإصدارات الأقدم لم يُنفذ.

التحقق من الشهادة يثبت مطابقة التوقيع للبصمة المعطاة، دون إثبات هوية ناشر
أو صلاحية سلسلة PKIX أو انتهاء الشهادة أو إبطالها. الكود الموثوق يعمل في
عملية المضيف؛ SecureClassLoader ليس عزلًا أمنيًا. إغلاقه لا يمحو الأصناف
المعرّفة أو نسخ الموارد التي سبق إرجاعها ولا يوقف خيوطًا عامة تنشئها إضافة.

## التحقق وحدوده

```sh
python3 scripts/test-extension-loader.py
python3 scripts/test-extension-archive-verifier.py
python3 scripts/test-runtime-host.py
```

تُبنى حزم اختبار من سورس مؤلف للمشروع وتُوقع بمفتاح اختبار مولد. لا توضع
حزمها أو أصنافها على classpath الأب. تشمل الحالات تحميل SourceFactory
واستدعاء مصادر فعلية من fixture، واستبدال المسار الأصلي بعد التحقق،
والموارد العربية وmulti-release وsealing والتوقيع والبيانات غير المطابقة،
ورفض التهيئة غير الصالحة، والإلغاء أثناء constructor والإزالة أثناء طلب.

نجحت 17 حالة على مضيف Java 27، وبقيت حالات التوقيع الـ47 وواجهات النماذج
والسجل ناجحة. النتيجة المحفوظة:
[extension-loader-host.json](../validation/extension-loader-host.json).
لم تدخل JAR منشورة أو ملفات العينة التنفيذية في اختبار التحميل.
تبقى Android/HttpSource والشبكة ومحوّل النماذج وربط Swift واختبار إضافة
حقيقية على iPhone ضمن ENG-03/05/06/09/11؛ لا تُغلق بهذه الاختبارات.
