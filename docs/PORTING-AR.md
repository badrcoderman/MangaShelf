# بدء نقل المكونات المفتوحة إلى مشروعنا

تاريخ المراجعة: ١١ سبتمبر ٢٠٢٦. هذه نتائج دراسة سورس فعلي وجرد العينة، وليست إعلان اكتمال تطبيق أو نجاح بناء iOS.

## ما نُفّذ

نُزّلت نسخة Git من [الخلفية المنشورة تحت حساب Tachimanga](https://github.com/tachimanga/Tachidesk-Server)، وثُبتت عند المراجعة `2e52214106ffab02d13ff61a620def78414a8a45`. تقع نسخة الدراسة في `../upstream/tachimanga-server` نسبة إلى مجلد المشروع. لم تُدمج ملفاتها التنفيذية أو ملفات العينة في هدف تطبيقنا.

النسخة تحتوي ٣١٣ ملف Kotlin و٣٥٨ ملف Java ضمن الملفات المتتبعة، بما فيها الاختبارات وطبقة توافق Android. هذه أعداد ملفات، ولا تمثل نسبة اكتمال التطبيق أو نسبة سورس Tachimanga المتاحة.

قُرئت ملفات البناء، ومسار الإضافات، وقناة التواصل مع الطبقة الأصلية. أضيفت أداة `scripts/inventory_reference_components.py` إلى مشروعنا، ونُفذت على الحزمة الموجودة دون تشغيلها. سجلت ٣٩ ملف بيانات Maven و١١٠٩ مجموعات إشعارات في موارد Flutter؛ مجموعات الإشعارات ليست عدد المكتبات الفريدة. النتائج في `REFERENCE-COMPONENTS.json`.

يشير بيان خلفية العينة إلى `suwayomi.tachidesk.MainKt` وTachidesk-Server. هذا يتوافق مع أصل الخلفية العام، لكنه لا يثبت مطابقة العينة للمراجعة المنشورة بايتًا أو سلوكًا.

## خريطة النقل

| الجزء | دليل المصدر | قرار التنفيذ |
| --- | --- | --- |
| خلفية المكتبة والتحديث والتنزيل | `server/src/main/kotlin/suwayomi/tachidesk` في النسخة المثبتة | مرشح للاستفادة من سورسه بعد فصل اعتماداته الخاصة؛ لا يُعلن مدمجًا بعد |
| واجهات توافق المصادر | حزم `eu/kanade/tachiyomi` وطبقة `AndroidCompat` | الحفاظ على عقود التوافق ومراجعة ترخيص كل جزء |
| تحميل JAR | `PackageTools.kt` يحتوي مسار تحميل أصناف من JAR | اختبار هذا المسار ضمن محرك معزول أولًا، ثم على iOS؛ لا يكفي وجود الدالة لإثبات التشغيل |
| فهرس المستخدم | `ExtensionGithubApi.kt` الذي قُرئ يستعمل JSON وبيانات APK؛ لم يظهر `jarUrl` أو `index.pb` في البحث النصي داخل سورس الخلفية وAndroidCompat | الاستفادة من محلل الفهرس الموجود في ReaderCore، وتحديد طبقة تكييف JAR صراحة؛ لا نستبدل مطلب المستخدم بمسار APK |

| شبكة النظام | `NativeNet.java` وملفات اعتراض الشبكة | يحتاج تنفيذًا أصليًا وتوافقًا مع معالجة الصور والكوكيز؛ لا نسخ مكتبات مجهولة من IPA |
| تخزين SQLite | ملف البناء يعتمد `libs/sqlite-jdbc-ios-3.41.0.0.jar` | تتبّع السورس والتعديلات والبناء الخاص بـiOS قبل اعتماده |
| المزامنة الخاصة | ملف البناء يعتمد `libs/cloud-api-1.0.0.jar`، وتستورد جداول عدة أنواع `app.tachimanga.cloud` | لا نفترض أن السورس متاح بسبب وجود الملف الثنائي؛ نفصل التبعية أو نوفر تنفيذًا مستقلًا للمزامنة |
| واجهة Flutter وDart | العينة تحتوي AOT وموارد وإشعارات تبعيات | وصف الشاشات والسلوك ثم إعادة التنفيذ؛ لم يُستعد مشروع Dart الأصلي |
| ميزات Mihon | [المستودع الرسمي](https://github.com/mihonapp/mihon) | مرجع لاحق لنماذج البيانات والسلوك؛ لم يُنزّل سورسه أو يُدمج في هذه الجولة |

## التراخيص والمنشأ

رخصة جذر الخلفية هي MPL-2.0، وتحتوي ملفات مثل NativeChannel وJavaChannel وExtensionGithubApi إشعارات صريحة بالرخصة وحقوق Tachimanga. توجد رخصة مستقلة داخل حزمة `eu/kanade/tachiyomi`، لذلك لا نعطي كل الملفات رخصة واحدة افتراضًا. [رخصة الخلفية المنشورة](https://github.com/tachimanga/Tachidesk-Server/blob/master/LICENSE).

نسخ الكود المفتوح يكون من المصدر المثبت مع الاحتفاظ بإشعاراته ومراجعة متطلبات توزيعه. وجود تبعية في ملف إشعارات Flutter أو ملف Maven يحدد مرشحًا للتحقق، ولا يمنح ترخيصًا للواجهة الخاصة أو يثبت أصالة ثنائيات العينة. ملكية مشروعنا الجديد لا تعني امتلاك حقوق المكونات التي كتبها الآخرون.

## أسلوب البنية الذي نستفيد منه

الخلفية تفصل نماذج البيانات والجداول والمتحكمات وتنفيذ الميزات وطبقة التوافق، وتستخدم Kotlin للمنطق وJava لواجهات أصلية محددة. نحتفظ بهذا الفصل عند الاستفادة من الكود، مع واجهات واضحة بين محرك المصادر والمكتبة والقارئ وطبقة iOS. لا نعتمد على أسماء أو بنية مطابقة للواجهة الأصلية دون سورسها.

يستمر مشروع SwiftUI الحالي إلى أن يثبت قرار بديل بنتيجة عملية. لن ننقل الواجهة إلى Flutter لمجرد أن العينة تستخدمه، ولن نعد بأن المشروع الحالي مطابق بصريًا. مطابقة الشاشات وسلوكها تُقاس على جهاز وبمرجع بصري لكل شاشة. تبقى متطلبات العربية وسجل التغييرات وإزالة المشاركة والتواصل والترجمة وأدوات المطورين ضمن خطة المنتج السابقة.

## محاولة البناء

الأمر الذي جُرّب من نسخة الخلفية:

```sh
./gradlew :server:compileKotlin --no-daemon --console=plain
```

Java 17 متاح. توقف Gradle Wrapper عند تنزيل Gradle 8.14.4 من `services.gradle.org` برسالة `Network is unreachable`. لذلك لم تبدأ ترجمة Kotlin، ولا توجد نتيجة نجاح أو فشل تخص توافق السورس نفسه. لم تُغيّر إعدادات الشبكة أو الحماية لتجاوز هذا القيد. كما لا تتوفر أداتا Swift وXcode في هذه البيئة بحسب فحص المسار.

## ترتيب العمل التالي

1. إكمال تجميع الخلفية في بيئة تستطيع جلب متطلبات البناء، مع حصر الملفات الثنائية التي ما زالت تحتاج سورسًا.
2. تحديد واجهة محرك المصادر المستقل واختبار مستودع المستخدم ودورة بحث وتفاصيل وفصول وصفحات، دون اعتماد على سحابة Tachimanga.
3. إثبات محرك Java مبني للآيفون وجسر النظام؛ نجاح المحرك على Linux أو macOS لا يثبت نجاحه على iOS.
4. نقل أجزاء المكتبة والتنزيل والتحديث القابلة لإعادة الاستخدام تدريجيًا، مع مقارنة تقدم القراءة والنسخ الاحتياطية.
5. إعادة تنفيذ الواجهة المطلوبة ثم الإضافات المتفق عليها. لا يعد حجم السورس المنسوخ معيارًا للاكتمال؛ المعيار وظائف تعمل على جهاز المستخدم.

هذه الجولة أنجزت تنزيل الخلفية المثبتة ودراسة أجزاء محددة وجرد المكونات ومحاولة بدء البناء. لم تنتج IPA جديدة، ولم تنقل التطبيق كاملًا أو تدمج محرك تشغيل JAR داخل تطبيقنا حتى الآن.
