# مراجعة SakurasoftLtd/tachiyomi-ios

تاريخ المراجعة: ١١ سبتمبر ٢٠٢٦.

## النتيجة

هذا المستودع هو محاولة قديمة لنقل Tachiyomi إلى iOS، لكنه ليس تطبيقًا مكتملًا ولا محرك مصادر جاهزًا. آخر commit متاح في الفرع `master` هو:

```text
ae1016a9683432a33fbc6bff955ae2f8a50409ad
2022-02-21 17:29:24 +0000
```

المشروع مفيد كمرجع لتقسيم شاشة iOS وتصميم التبويبات، ولا يصلح أساسًا مباشرًا لمشروعنا دون إعادة بناء المحرك والبيانات.

## ما يحتويه فعليًا

- تطبيق UIKit قديم، وليس SwiftUI.
- ٢٦ ملف Swift داخل كود التطبيق، إضافة إلى ملفات CocoaPods الموردة.
- تبويبات: المكتبة، التحديثات، السجل، التصفح، والمزيد.
- شاشة مكتبة تستخدم `UICollectionView` و`RxDataSources`.
- شاشة التصفح مقسمة إلى المصادر والإضافات بواسطة `UISegmentedControl`.
- نموذج `Source` بسيط محفوظ عبر SharkORM.
- تهيئة أول تشغيل تنشئ مصدر التخزين المحلي.
- قائمة المكتبة الحالية تستخدم ستة عناوين ثابتة عبر `Observable.just` وتحتوي تعليق `TEMP Source`.
- شاشتا التحديثات والسجل وشاشة المزيد لا تحتوي منطقًا وظيفيًا حقيقيًا في هذه المراجعة.
- شاشتا المصادر والإضافات تعرضان حالة فارغة؛ لا يوجد جلب فهرس أو تحميل إضافة أو بحث أو تفاصيل أو قارئ.

## التبعيات والإعدادات

ملف `Podfile.lock` يثبت:

| التبعية | الإصدار |
| --- | --- |
| RxSwift / RxCocoa / RxRelay | 6.2.0 |
| RxDataSources / Differentiator | 5.0.0 |
| SharkORM | 2.3.62 |
| SnapKit | 5.0.1 |

يحدد مشروع Xcode حد iOS عند 14.5، ويضع `TARGETED_DEVICE_FAMILY = 2`، أي أن إعداد الهدف الملتزم في الملف موجه إلى iPad فقط. كما يحتوي ملف المشروع على `DevelopmentTeam` ومعرّف حزمة باسم المطور؛ لا ننقل هذه القيم إلى مشروعنا.

## ما يمكن أخذه كمرجع

1. ترتيب التبويبات والتنقل داخل `RootTabBarController` و`NavigableTab`.
2. فصل كل تبويب داخل `UINavigationController`.
3. تقسيم شاشة التصفح إلى مصادر وإضافات.
4. نمط الخلية والقائمة الفارغة وحالات عدم وجود نتائج.
5. ألوان وهوية واجهة Tachiyomi العامة، بعد إعادة تنفيذها بعناصر مشروعنا وبهوية مستقلة.

## ما لا يمكن اعتباره منقولًا

المستودع لا يوفر تنفيذًا لمحرك Tachiyomi أو Mihon، ولا يوفر تشغيل JAR، ولا بروتوكول مستودعات، ولا قارئ صفحات، ولا تنزيلات أو تتبع أو نسخًا احتياطية. لذلك لن يحل مشكلة نقل إضافات Tachimanga إلى iOS، ولن نعلن أن استخدامه يحقق توافق Tachiyomi.

## الرخصة والمنشأ

لم يوجد ملف `LICENSE` أو `NOTICE` في جذر المستودع، وواجهة GitHub لا تعرض رخصة للمستودع عند هذه المراجعة. ملفات Pods تحتوي رخص مكونات منفصلة، لكنها لا تمنح رخصة لكود التطبيق نفسه. لهذا نستخدمه كمرجع دراسة فقط، ولا ننسخ كود التطبيق إلى MangaShelf قبل الحصول على رخصة واضحة أو إذن من صاحب المستودع. هذا منفصل عن رخصة Mihon أو Tachidesk-Server.

## المراجعة الساكنة للاتصالات

لم تظهر في كود التطبيق نفسه طلبات شبكة أو تنفيذ أو تحميل مكتبات. توجد داخل نسخة `Pods/SharkORM` وظيفة مزامنة اختيارية بعنوان افتراضي `https://api.testingallthethings.net/Api/Sync`، لكن التطبيق المستعرض لا يستدعي `SharkSync.startService` ولا يستخدم `SRKSyncObject`. مع ذلك، هذا سبب إضافي لعدم إدخال Pods الموردة إلى MangaShelf؛ سنستخدم تخزينًا محليًا معروف المصدر ونكتب مزامنتنا بعناوين يحددها المستخدم.

## قرار مشروع MangaShelf

نحتفظ بمشروعنا SwiftUI مستقلًا، وننقل الأفكار القابلة لإعادة التنفيذ من هذا المستودع دون نسخ هويته أو إعدادات توقيعه أو تبعياته القديمة. الأولوية التنفيذية هي:

1. بناء واجهة تبويبات Tachimanga على نموذج بيانات MangaShelf الحالي.
2. إنشاء عقد محرك المصادر الذي يدعم فهرس `index.pb` وJAR بعد التحقق.
3. اختبار مسار مصدر واحد كامل: مستودع، إضافة، بحث، تفاصيل، فصول، صفحات.
4. إضافة التنزيلات والتحديثات والسجل بعد نجاح المسار السابق.

نجاح بناء IPA الحالي يثبت ترجمة مشروعنا فقط؛ لا يثبت أن هذا المستودع أو إضافات JAR تعمل على iOS.
