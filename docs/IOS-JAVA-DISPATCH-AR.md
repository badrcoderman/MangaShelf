# وصل موزّع الأوامر بـJava

أضيف `runtime-native/MSJavaBridge.c` لربط `ms_bridge_dispatch` بواجهة JNI
الفعلية، بعد بدء VM صراحة واختيار صنف وطريقة ثابتين يملكهما التطبيق.
اختبار المضيف يستدعي التسجيل نفسه؛ لا يستخدم نتيجة مصطنعة بدل JNI.

## التنفيذ والتحقق

- تعيد `ms_java_call_string2_owned` استجابة UTF-8 مملوكة للمستدعي، بسقف
  16 MiB واستدعاء Java واحد. طولها يستثني NUL الختامي، وتحرر بواسطة
  `ms_java_free_string`.
- يحتفظ الاستدعاء بنطاق JNI محلي، ولا يشارك JNIEnv بين الخيوط، ويحافظ
  على استثناء موجود لدى مستدعٍ مرفق مسبقًا؛ يفصل الخيوط التي أرفقها فقط.
- يمنع تعطيل التسجيل/إزالته التقاط أوامر جديدة، بينما قد تكمل الأوامر
  الملتقطة سابقًا. لا يعني ذلك إلغاء Java أو إغلاق VM أو تفريغ الأصناف.
- تبقى واجهة المخزن الثابت مدعومة. BUFFER يعني أن الأمر نُفذ بالفعل؛
  إعادة استدعائه بمخزن أكبر قد تكرر أثره. واجهة Swift الحالية لا تعيد
  الأمر، لكنها ما زالت تحتاج ربط واجهة الاستجابة المملوكة للردود الكبيرة.
- يرفض محوّل JSON/C-string وجود NUL مضمّن، بينما تحفظه واجهة JNI العامة
  المملوكة مع الطول. فشل حل الصنف قد يشمل تبعية مفقودة أو تهيئة سابقة فاشلة.

شُغّل `python3 scripts/test-java-bridge.py` على Java 27 مع Java helpers
مؤلفة للمشروع. اجتاز ردًا كبيرًا وUnicode، وتجاوز المخزن دون إعادة التنفيذ،
والحدود وNUL واستثناء Java وفشل الحل والتهيئة والتعافي، وحفظ الاستثناء
والارتباط السابقين، وأربعة عمال متزامنين وتعطيل backend أثناء استدعاء حي؛
[الأوامر والبصمات والنتيجة](../validation/java-bridge-host.json).

كشف الاختبار القديم افتراضًا متقادمًا أن نتيجة RuntimeProbe تقل عن 64 بايت.
أعيد إنتاج exit 20 بكود runtime من HEAD، ثم استبدل الاختبار هذا الافتراض
باستجابة مملوكة، ونجح الفحص القديم للـNativeNet/Channel؛
[إثبات المقارنة](../validation/java-runtime-owned-regression.json). تغير تعليق
توضيح حالة حل الصنف في الرأس لاحقًا؛ الفحص المركز الأحدث يغطي الرأس الحالي.

## شبكة Swift

أصبح تسليم نتيجة `NativeBridge` محميًا بقفل وحالة انتظار/اكتمال/مهلة.
تلغي المهلة مهمة النقل، ولا تستبدل النتيجة باستجابة متأخرة. أضيفت هوية
للمستمع وإزالته، مع تنفيذ callbacks وتحرير مالكيها خارج القفل.

اجتازت الحالات الخمس الجديدة ضمن **130 اختبار Swift** وبناء IPA غير موقعة
في [39843341792](https://github.com/badrcoderman/MangaShelf/actions/runs/39843341792)
عند `46d01ce`. تشمل إلغاء طلب URLSession حقيقي عبر URLProtocol اختباري،
واستجابة متأخرة، و32 استدعاء متزامنًا، وفصل الجسم الثنائي، وإزالة مستمع
مع dispatch متداخل. هذا اختبار لمسار Swift؛ لم يصل بعد إلى NativeNet
المستخدم داخل إضافة حقيقية على iPhone.

للـVM وJAR المشروع وMIME وUnicode، قبل إضافة هذا المحوّل. يبقى اختبار
المحوّل الجديد على iOS، وربط استجاباته المملوكة بـSwift، ومضيف Source 1.6
وAndroid/الشبكة، والتحقق من ثقة الملف المستخدم للتحميل، ثم مصدر حقيقي.
