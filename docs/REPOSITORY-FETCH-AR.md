# إصلاح تحليل روابط المستودعات والإلغاء في MSL

## المشكلة التي ظهرت في مراجعة المصدر

كان `RepositoryDecoder` يستدعي validate قبل أن يتمكن RepositoryClient من
حل روابط JAR والصور النسبية. بذلك يرفض الفهرس قبل الوصول إلى كود حل الروابط.
وكانت قائمة الإضافات المنفصلة تستخدم قاعدة الفهرس الأصلية بدل عنوان ملف القائمة،
ومحاولات الفهرس البديل تلتقط أخطاء الإلغاء ثم تستمر إلى طلب آخر.

## التغيير

- يقبل decode وdecodeExternalList سياقًا اختياريًا بعنوان المستند. تُحل روابط
  JAR والصور وقائمة الإضافات بهذا العنوان **قبل** التحقق النهائي من HTTPS.
- يحل كل ملف روابطه بحسب عنوان طلبه؛ قائمة داخل `lists/entries.json` لا تورث
  دليل `index.pb` عندما تحمل رابط صورة مثل `icons/source.png`.
- لا يُخمن رابط JAR عند غيابه، ولا تتحول روابط مواقع المصادر إلى مسارات مستودع.
- قائمة JSON المضمنة الفارغة تظل قائمة موجودة، فتسبق رابط القائمة المنفصلة.
- CancellationError وURLError.cancelled يخرجان من fallback فورًا؛ وتوجد فحوص
  Task cancellation قبل الطلبات وبعد النقل والتحليل وقبل إرجاع النتيجة.
- بقي مخطط التخزين والتحقق من بيانات المكتبة القديمة كما هو؛ لم تُضف قيود
  جديدة تجعل مستودعات محفوظة ذات رابط قائمة نسبي غير قابلة لفتح المكتبة.

## التحقق المطلوب

أضيفت خمسة اختبارات Swift تغطي سياق الروابط النسبية، ملف قائمة في دليل مختلف،
رفض روابط غير آمنة، القائمة المضمنة الفارغة، وعدم طلب repo.json بعد نوعَي الإلغاء.
نجحت الحالات الخمس ضمن **72 اختبار Swift** في
[39482382728](https://github.com/badrcoderman/MangaShelf/actions/runs/39482382728)
عند `bf9ac4221d41f07b4a49416dfab2990650cba7c4`، ثم نجح بناء ARM64 بـSDK 26.
فُحص IPA الناتج: CRC لكل 66 مدخلة، وMach-O arm64/iOS 26.0، ودون توقيع أو
provisioning profile. [بيانات البناء والبصمات](../validation/ios-39482382728.json).
الاختبارات على macOS، وليست تشغيلًا لهذه الحالات أو لمصدر فعلي على iPhone.

## حدود هذا الإصلاح

تبقى SRC-07 مفتوحة: schema JSON الحديثة وrepo.json/index_v2 و404 وCDN تحتاج
تنفيذًا واختبارات مستقلة، وفق [التحليل](TACHIMANGA-5.1-REPOSITORIES-AR.md).
واجهة النقل الحالية تعيد Data فقط، فلا تنقل عنوان HTTP النهائي بعد التحويل؛
سياق الحل هنا هو عنوان المستند المطلوب، وليس ادعاء دعم إعادة توجيه إلى دليل
مختلف. لا يثبت هذا الإصلاح تشغيل JAR أو صحة توقيع ناشر أو مصدر على iPhone.
