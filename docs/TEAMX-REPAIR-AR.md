## عطل مضيف مثبت من المصدر

ينشئ `parseMangaDetails` في
[TeamX.kt](https://github.com/keiyoushi/extensions-source/blob/1d3d7c4b3e876fb0c26ae3ade8113fb329af15fa/src/ar/teamx/src/eu/kanade/tachiyomi/extension/ar/teamx/TeamX.kt)

24 أكتوبر؛ Git blob هو `8ac0628fdf957951f09c1f106ee851239b7a9258`.
كان محول MSL يقرأ url غير المهيأ أثناء تحويل التفاصيل، فيفشل التحديث قبل
الوصول إلى حفظ الفصول. يتعامل
[UpdateMangaFromRemote في Mihon](https://github.com/mihonapp/mihon/blob/d001e6f210e6a077a30dd9a1392573a3225bba2f/app/src/main/java/mihon/domain/source/interactor/UpdateMangaFromRemote.kt)
مع النتيجة كتحديث للبيانات الوصفية على الهوية الحالية، ولا يستبدل رابطها.

أصبح المحول يحتفظ برابط البحث والعنوان السابق إذا لم تعيّن النتيجة عنوانًا.
يمرر التطبيق طلب update واحدًا للتفاصيل والفصول بدل طلبين. تُسلسل تحديثات
العنوان نفسه فقط لأن KeiSource يرفض تداخلها؛ تزال الأقفال غير المستخدمة
بعد الإنجاز أو الإلغاء. لا يتغير ترتيب الفصول العائد ولا تُقطع القائمة.

أضيف اختبار نتيجة جزئية بلا url مع 1,201 فصل، وعنوان غير مهيأ، ورابط عائد
مختلف، وطلبين متداخلين. نجحت حالات المحول التسع محليًا قبل إضافة تصنيف
أخطاء الشبكة؛ التحقق الكامل من commit النهائي في CI يبقى مطلوبًا.

لا يثبت هذا أن كل نقص في الفصول سببه هذا الخطأ. يجلب كود Team X صفحات
الفصول ويستبعد الفصول المقفلة بنفسه. يلزم مقارنة عنوان فعلي وعدد صفحاته
مع الإصدار الذي لدى المستخدم، ثم اختبار الجهاز بعد الإصلاح.

## تشخيص الفشل

أصبحت استجابات المضيف تميز HTTP ورقم الحالة، وTLS، والتحقق بالمتصفح،
وفشل الشبكة واعتماد API غير مدعوم. يعرض Swift رسالة مناسبة ويحفظ تصنيفًا
ثابتًا ورقم HTTP فقط في التشخيص، دون نص استثناء المصدر أو روابط أو كوكيز.
أضيفت حالات فعلية في fixture الموقعة وحالات Swift لفك الرسالة ومنع تسريب
النص البعيد. يضم التقرير ورقم «حول» إصدار التطبيق ورقم البناء معًا.

أضيف اختيار Team X إلى بناء المصدر العام المثبت نفسه المستخدم لـMangaDex.
يُراجع artifact وهوية المصدر وبصمته قبل أي تشغيل؛ لا تُستخدم حزمة من IPA
المرجعية ولا تمنح شهادة debug ثقة ناشر للإصدار المنشور.
