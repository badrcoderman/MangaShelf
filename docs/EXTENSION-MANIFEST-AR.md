# بيانات تحميل JAR الإضافة

## سبب التعديل

المسار السابق في `ensureExtensionLoaded` يمرر الحزمة ومسار JAR دون صنف
التشغيل الذي يطلبه runner، ويعود دون خطأ إن لم يجد مخزنًا أو سجلًا نشطًا.
كان كذلك يرسل مسار الملف دون إعادة التحقق من بصمته أو فحص محتواه قبل التحميل.

أثبت [التحليل الثابت](TACHIMANGA-5.1-JAVA-AR.md) أن JAR المحوّل يحمل
`AndroidManifest.xml` كنص UTF-8، وأن مدخل التشغيل هو
`tachiyomi.extension.class`، مع إضافة packageName إذا بدأ الاسم بنقطة.
وجود `factory` في metadata لا يحدد نوع الكائن: يميز المرجع `Source` عن
`SourceFactory` بعد إنشاء الكائن. التعديل الحالي لا ينفذ هذا التمييز أو ABI.

## التنفيذ

- قارئ مستقل للـXML بحد 256 KiB، دون DTD أو تعريف كيانات أو حل موارد خارجية؛
  حدود للعمق وعدد العناصر والصفات، والتحقق من namespace الخاص بصفات Android
  بما في ذلك aliases وإعادة تعريفها ضمن العناصر.
- يستخرج هوية الحزمة وversionCode العشري وversionName وصنف التشغيل؛ يتطلب
  علامة `tachiyomi.extension` وmetadata مباشرة تحت application واحدة. يقبل
  أسماء Java من ASCII مع `_` و`$`؛ الأسماء غير المشمولة تُرفض ولا تُعدل بصمت.
- لا يُخلط `META-INF/MANIFEST.MF` مع AndroidManifest. تتأكد قراءة JAR من وجود
  مدخلة `.class` المطابقة لصنف التشغيل، دون تحميلها أو تنفيذها. manifest
  الثنائي الخاص بـAPK ليس XML نصيًا مدعومًا بهذا المسار.
- يرفض staging عدم تطابق هوية manifest وإصدارها مع فهرس المستودع؛ لا يستبدل
  السجل السابق عند الفشل ولا يمنح الثقة أو التفعيل من مجرد وجود manifest.
- يعيد مرشح التحميل قراءة الثقة وحالة التفعيل والتحقق من SHA-256 وفحص JAR
  في عملية actor واحدة، ثم يمرر الصنف المقروء من البايتات إلى dispatcher.
  metadata المخزنة في JSON ليست سلطة لاختيار صنف التشغيل.
- غياب المرشح أو الثقة أو نية التفعيل يُرجع خطأ قبل استدعاء المحرك.
  تبقى سجلات inspection القديمة دون الحقل الجديد قابلة للفك.

## التحقق والحدود

تضم `ExtensionManifestTests` حالات XML والأسماء والحدود والإصدار الكبير
والكيانات والـnamespace المزيف، والتطابق مع JAR والفهرس، وتغيير ملف الحزمة،
وتزوير inspection المحفوظ، وتمرير الصنف إلى dispatcher الاختباري.
الملفات الثلاثة الجديدة في test Fixtures مؤلفة للمشروع وتحتوي رؤوس class
اصطناعية فقط؛ ليست إضافة قابلة للتشغيل ولا تدخل تطبيق الإنتاج.

لم تُشغّل اختبارات Swift محليًا؛ البيئة Linux بلا Swift/Xcode. يلزم تسجيل
نتيجة Actions قبل نسبة النجاح لهذه الحالات أو لبناء iOS.

لا يغلق التعديل ENG-03 أو ENG-05 أو ENG-06: تسجيل معرّفات المصادر المتعددة
وSourceFactory وتبعيات Android/Kotlin/Rx/OkHttp ما زال مطلوبًا، والمحرك نفسه
ينتظر بناء صورة كاملة وفحص iPhone. هذا التحقق ليس مصادقة للناشر ولا يزيل
احتمال تغير الملف بين الفحص وقراءة ClassLoader له؛ يجب حسم الربط بالملف
المتحقق منه قبل تفعيل المحرك للإنتاج.
