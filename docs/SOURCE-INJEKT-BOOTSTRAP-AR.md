# خدمات بدء المصدر وInjekt — تقدم جزئي

يطلب مساعد `keiyoushi.utils.applicationContext` في مصدر MangaDex المثبت
`Injekt.get<Application>()`. نُفذت الآن خدمات التطبيق التي يحتاجها هذا الطلب
داخل مضيف JVM. لا تعني هذه الخطوة أن MangaDex أو تطبيق iPhone يعملان بالمحرك.

## المصدر والبناء

- المكتبة العامة: [null2264/injekt](https://github.com/null2264/injekt/tree/4135455a2a744796967b3b4a38764c699d340aa7)،
  المراجعة الكاملة `4135455a2a744796967b3b4a38764c699d340aa7`، المطابقة لدبوس
  `4135455a2a` في dependencies الخاصة بمصدر الإضافات المثبت.
- حُفظت ملفات Kotlin التسعة ورخصة MIT الأصلية، دون Gradle أو wrapper أو JAR
  منشورة. تحققت أحجام الملفات وGit blob SHA-1 وSHA-256 قبل البناء؛
  `runtime-host/injekt-source.lock.json` يثبت المجموعة الكاملة.
- يرفض Kotlin 2.4 وصول public inline إلى الخاصية protected في `LocalScoped`.
  يضيف `injekt-compat.patch.json` جسر `PublishedApi` داخليًا ويحفظ getter
  الأصلي protected والطرق الأصلية. يُطبق التغيير على نسخة بناء مؤقتة فقط، مع
  مطابقة بصمتي المدخل والمخرج. ملفات upstream المخزنة غير معدلة.
- تُبنى المكتبة بأدوات Kotlin المثبتة وبـ`-Werror`، ثم يُبنى كود MSL بالصرامة
  نفسها. تحفظ module metadata مستقلة ورخصة MIT داخل JAR المضيف. هذا بناء من
  مصدر عام مرخّص، وليس نقل كود تنفيذي من عينة Tachimanga.

## دورة الخدمات

ينشئ `HostServices.configure` سجل Injekt جديدًا يربط الأنواع التالية قبل إنشاء
أي مصدر:

| نوع الطلب | الكائن المعاد |
| --- | --- |
| `android.app.Application` | التطبيق المالك للملفات والتفضيلات |
| `android.content.Context` | التطبيق نفسه |
| `NetworkHelper` | عميل شبكة المضيف نفسه |

لا تنشر خدمات جديدة عند فشل التهيئة، وتبقى ملكية context للمستدعي عند الفشل.
بعد نجاحها، يملك المضيف السياق. الإغلاق والإعداد متسلسلان؛ يُمسح سجل Injekt
الذي يملكه المضيف ويُغلق الكاش وتُصرف كتابة التفضيلات. تظهر أخطاء الإغلاق حتى
بعد مسح الخدمات العامة. يجب تصريف سجل المصادر أولًا واستدعاء الإغلاق من عامل.
المكتبة ليست sandbox؛ لا ضمان لتنظيف كائنات يحتفظ بها plugin في globals خاصة.

## التحقق المحلي

```sh
python3 scripts/test-runtime-bootstrap.py
python3 scripts/test-extension-loader.py
python3 scripts/test-runtime-host.py
```

نجحت الحالات الست لبدء الخدمات: مطابقة الأنواع، inline عبر module مستقلة مع
حفظ getter protected، إعادة فتح التفضيلات بعد مسح الخدمات، فشل البدء الجزئي،
رفض البدء المكرر، وإظهار فشل كتابة التفضيلات عند الإغلاق.

نجحت حالات التحميل الـ19، وتتضمن الآن مصدر HTTP مؤلفًا في JAR موقعة يطلب
Application وContext وNetworkHelper عبر Injekt داخل منشئه. زاد عداد تفضيلاته
من 1 إلى 2 بعد إزالة الحزمة وإعادة تثبيتها دون فقد إعداداتها، مع طلب HTTP فعلي.
بقيت مطابقة ABI للأصناف الـ32 والأعضاء الـ222 وفحوص النماذج الـ14 والسجل الـ20
ناجحة. هذه نتائج مضيف، لا تنفيذًا للحزمة المنشورة أو iOS.

## المتبقي

`ConfigurableSource` وصفوف التفضيلات وحقول المنصة وJSON/compression مطلوبة
للمصدر الكامل. كشف فحص مصدر `zstd-kmp-jvm:0.4.0` أن loader الأصلي يدعم أسماء
Windows/Linux/mac فقط، ويستخرج مكتبة أصلية مؤقتة. تقرير الهاتف يحدد `os.name`
كـ`Darwin`؛ هذا مسار غير مدعوم في ذلك loader. المطلوب بناء JNI/codec لـarm64
iOS من مصدر مرخّص ومسار تحميل مناسب، ثم إثباته على الهاتف؛
[الأدلة الثابتة](../validation/zstd-ios-static-review.json).

لا توجد IPA جديدة بهذه الخطوة. ربط Swift ومحوّل النماذج وثقة الناشر وتدفق مصدر
حقيقي على iPhone، ثم المطابقة البصرية والنسخ المتوافقة، ما زالت غير مكتملة.
