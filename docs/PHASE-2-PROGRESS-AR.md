# تقدم المرحلة الثانية

## مراجعة صور الإعدادات — 15 سبتمبر 2026
- قائمة الثلاث نقاط أصبحت سطحًا داكنًا معتمًا بعرض أقصى 264 نقطة وحواف 16 نقطة، دون glassEffect أو تمدد بعرض الشاشة. بقيت حركة ظهور شفافية قصيرة فقط وتُعطّل مع Reduce Motion.
- حسّنت صفوف الإعدادات: فصل العنوان والوصف، التفاف الوصف، مفاتيح 52×32 مع منطقة لمس 56×44 وحركة قصيرة للمفتاح فقط.
- عطّلت حركة الانتقال في TachiNavigationRow والعودة في tachiPage؛ بقية NavigationLink وشاشات القراءة تحتاج مراجعة مستقلة، ولا ندعي إلغاء جميع حركات التطبيق.
- حول تستخدم ترويسة رمزية كبيرة وقسم إصدار بأيقونة وروابط المساعدة والتراخيص، مع إبقاء سجل التغييرات المطوي. لا نضيف اتصل بنا أو حواجز مدفوعة.
- أدوات المطور متاحة مباشرة في المزيد، مع عدد الحزم المجهزة وخيارات التسجيل وحدود الأغلفة والفحوص والتخزين والتقرير الموجودة، دون أزرار تشغيل محرك وهمية.
- صور المستخدم مرجع بصري. تعذّر فتح مستودع tachiyomi_flutter عبر أداة الويب؛ لم ينسخ منه كود في هذه المراجعة.
- هذه تحسينات جزئية وليست إغلاقًا للمرحلة: محرك JAR والاختبار على جهاز والمطابقة البصرية الكاملة ما زالت مطلوبة.

## المنفذ في المصدر
- قائمة عائمة مشتركة لخيارات المكتبة والتحديثات، وأيقونات ودعم اتجاه اللغة وإغلاق بالنقر خارجها وإجراء الهروب لقارئ الشاشة.
- ربط الإجراءات الموجودة: الاستيراد، إدارة التصنيفات، تحديث المكتبة والتنزيلات.
- ألوان داكنة أعمق ونصوص وتحديد أوضح.
- استخدام glassEffect لشريط التبويبات والقائمة، مع خلفية معتمة عند تقليل الشفافية واحترام تقليل الحركة.
- الحد الأدنى للتطبيق iOS 26.0، وفحص SDK 26 في مسار البناء. الإنجليزية افتراضية والعربية اختيارية.

## ما لم يكتمل
- تشغيل JAR: لا يحتوي المشروع محرك JVM. قراءة الفهرس ليست تشغيلًا للإضافة.
- الدراسة السابقة لخلفية Tachimanga تشير إلى NativeChannel وتبعيات iOS يلزم بناء بدائلها من المصدر؛ لم يتم التحقق من بناء تلك الخلفية.
- فشل جلب مستودع الخلفية واتصال GitHub بسبب اتصال الوكيل الشبكي في بيئة العمل. لم تُنقل مكتبات النسخة المعدلة.
- لا تتوفر Xcode أو Swift محليًا. فحص الموارد لا يثبت نجاح تجميع Swift أو صحة المظهر على الجهاز.
- يلزم بناء IPA ثم اختبار القائمة باللغتين، أحجام النص الكبيرة، VoiceOver، تقليل الشفافية وشريط الزجاج فوق الأغلفة.
- بقية قوائم التفاصيل لم تتغير. لا ندعي مطابقة بصرية نهائية أو اكتمال المرحلة الثانية.

## بوابة إغلاق المرحلة
إضافة JAR حقيقية تنفذ البحث والتفاصيل والفصول والصفحات على iPhone، مع دورة تثبيت وتحديث وإزالة وتفضيلات وثقة؛ ثم نجاح البناء والمراجعة البصرية.

## استمرارية مفتاح المستودع
أضيف رفض تغيّر أو اختفاء المفتاح المحفوظ في مساري التحديث والإضافة المكررة للرابط، قبل الكتابة على القرص. يبقى الفهرس السابق محفوظًا عند الرفض وتظهر رسالة باللغتين. يسمح للمستودع غير ذي المفتاح باكتساب مفتاح في تحديث لاحق؛ هذه سياسة استمرارية فقط وليست تحققًا تشفيريًا من الفهرس أو JAR. أضيف اختبار لمساري الرفض وبقاء القرص والذاكرة دون تغيير ثم نجاح تحديث بنفس المفتاح وإعادة فتح التخزين. الاختبار لم يُشغّل لعدم توفر Swift محليًا.

## نتيجة البناء اللاحقة — تحل محل قيود الاتصال والبناء أعلاه

## بدء اختبار محرك JAR — 14 سبتمبر 2026
استُعيدت نسخة الخلفية عند المراجعة المثبتة 2e52214106ffab02d13ff61a620def78414a8a45. فشل Gradle محليًا عند تنزيل التوزيعة قبل بدء التجميع؛ أضيف مسار GitHub Actions مستقل لتجميع السورس المثبت وحفظ السجل، دون إدخال ناتجه إلى IPA.

أضيفت أداة scripts/inspect_jar_backend.py لإنتاج JAR-BACKEND-INVENTORY.json من ملفات Git المتتبعة. أحصت 51 تصريحًا لدوال Java أصلية في 10 ملفات، و7 ملفات تستورد أنواع السحابة، و4 ملفات JAR متتبعة بما فيها Gradle wrapper. هذا جرد ساكن لا يثبت أن كل الدوال قابلة للوصول أو مطلوبة لكل مصدر. الملفات الأصلية الأهم للجسر: NativeChannel، NativeNet، Bitmap، McCookieManager، WebView، QuickJs وNativeString. لا يوجد تنفيذ Swift/C للجسر ضمن الملفات المتتبعة التي راجعناها.

حدود اختبار الخلفية: قد يستعمل التجميع تبعيات JAR المرفقة بالمستودع العام؛ نجاحه لا يثبت توافر سورسها ولا صلاحيتها للتوزيع في تطبيقنا. نحتفظ بها في checkout الدراسة ولا نضيفها إلى مشروع التطبيق. لم يُختَر أو يُدمَج JVM للآيفون بعد.

### النتيجة المؤكدة لاختبار الخلفية
نجح الأمر `:server:compileKotlin` في GitHub Actions على Linux وJava 17، عند نفس المراجعة المثبتة. التشغيل: https://github.com/badrcoderman/MangaShelf/actions/runs/34791789590 . سجل Gradle يعلن `BUILD SUCCESSFUL` و15 مهمة منفذة. الدليل المختصر وقائمة المهام في JAR-BACKEND-BUILD.json؛ السجل الكامل محفوظ ضمن artifacts التشغيل.

هذه نتيجة تجميع Kotlin مع تبعيات المستودع المرفقة؛ لا تثبت بناء جميع Java في الخادم أو بدء الخادم أو تنفيذ إضافة أو وجود JVM يعمل على iPhone. توجد تحذيرات تقادم في Gradle وKotlin، لذلك يبقى الاختبار مثبتًا على نسخ المشروع الحالية.

الخطوة التالية: إثبات JVM مبني من المصدر على iOS 26 يدعم تحميل الأصناف ديناميكيًا، ثم تنفيذ الجسر الأصلي المطلوب للمصدر التجريبي. لا يُنقل الخادم كاملًا إلى التطبيق ولا تُضاف أزرار تثبيت وهمية قبل هذا الإثبات.

## 15 سبتمبر — دمج الواجهة وعقد الشبكة
- أضيفت موارد الواجهة المستخرجة والخطوط، وأصلح إطار قائمة الخيارات ليقاس بالمحتوى. الموارد الـ52 لا تعني عرض جميع الصور في الشاشات.
- أضيف NativeNetworkContract.swift كتطبيق مستقل لعقد بيانات NativeNet: JSON للطلب، جسم منفصل، خيارات الكوكيز والتحويلات، وبيانات الرد مع الجسم في مصفوفتين منفصلتين.
- أضيفت اختبارات للعقد وخيارات null وتطابق الجسم ورفض المخططات غير الشبكية والترويسات غير الصالحة. لم تشغّل لغياب Swift محليًا.
- هذا عقد بيانات فقط، وليس URLSession transport أو JNI أو JVM. تطبيق followRedirects يحتاج delegate أثناء التنفيذ.
- بناء JVM السابق غير متحقق النتيجة حاليًا، ورفع commit الواجهة تعذر لغياب اعتماد GitHub. لا تزال المرحلة مفتوحة حتى تشغيل إضافة فعلية على iPhone.

## تنفيذ نقل NativeNet
أضيف NativeNetworkTransport كتنفيذ HTTP فعلي فوق URLSession: جسم منفصل، رد محدود الحجم أثناء الاستقبال، مهلات، إلغاء، سياسة كوكيز، وحد أقصى للتحويلات ومنع التحويل من HTTPS إلى HTTP وإزالة بيانات الاعتماد عند تغير المضيف. لم يربط بعد بدالة JNI، ولم تُشغّل اختبارات Swift أو نقل HTTP لهذا التنفيذ.

محاولة `bash scripts/build-ios.sh unsigned` توقفت قبل التجميع برسالة أن Xcode على macOS مطلوب. هذا عائق بناء حالي، وليس نتيجة فشل Swift. لا توجد مكتبة JVM iOS متحققة بالمشروع حتى الآن، ولا تزال بوابات الإغلاق السابقة مطلوبة. أحدث وصول GitHub فشل بسبب غياب الاعتماد؛ لم ترفع التغييرات الجديدة.

## تجهيز حزم JAR محليًا
أضيف JARInspection لفحص أرشيف الإضافة ضمن حدود الحجم وعدد الملفات وفحص CRC لجميع المدخلات، واستخراج manifest وتسجيل أسماء ملفات class وأعلى إصدار لها. فحص رأس class ليس verifier كاملًا ولا يثبت التوافق التنفيذي؛ يظل تحقق JVM مطلوبًا.

أضيف StagedExtensionStore لحفظ الحزم حسب SHA-256 مع فهرس ذري، ورفض بصمة غير مطابقة والرجوع لإصدار أقدم وتغيير محتوى رقم إصدار ثابت. تدعم الطبقة تجهيز إصدار وتحديث السجل وإزالته والتحقق من الملف قبل تسليمه لاحقًا للمحرك. تحفظ الملفات غير المرجعية لتجنب حذف حزمة قد يستعملها JVM مستقبلًا. البصمة المتوقعة تحتاج قرار ثقة مستقل؛ لم ننفذ تحقق توقيع مستودع بهذا التغيير.

هذه الطبقة ليست مدير إضافات مفعّلًا في الواجهة ولم تربط بـJVM. لا تزال عملية التجميع واختبار Swift مؤجلة، ولم يتم الرفع وفق طلب المستخدم. مرحلة التشغيل على iOS غير مكتملة.

## 15 سبتمبر — منسق المستودعات والتجهيز الساكن
- أضيف `RepositoryClient` إلى النواة لتوحيد جلب الفهرس، حل قائمة الإضافات المنفصلة، والتحقق من HTTPS قبل أي طلب. عند فشل فك `index.pb` بعد استجابة ناجحة، يجرب المنسق فقط أسماء الأشقاء الموثقة `index.min.json` و`repo.json`؛ لا يخفي أخطاء الشبكة ولا يفتح مسارات عشوائية.
- توسع محلل JSON ليدعم قائمة `index.min.json` وأغلفة `extensions`/`data`/`items`، مع بدائل `packageName` و`versionCode` و`jar` و`icon`. أضيف تحقق حدودي للهوية واللغات والروابط قبل حفظ الفهرس.
- أضيف تنزيل JAR محدود الحجم مع فحص CRC ورؤوس class وحساب SHA-256 قبل التخزين. واجهة المستودع تعرض نتيجة الفحص وتطلب قرارًا صريحًا لتجهيز الحزمة؛ التجهيز تخزين ذري فقط ولا يعني تثبيتًا أو ثقة أو تنفيذًا.
- أضيف تخزينًا دائمًا لسجل الحزم المجهزة وربطه بواجهة الإضافات مع إزالة آمنة. لا تزال الحزم المجهزة غير قابلة للتشغيل حتى بناء JVM والجسر واختبارهما على جهاز iPhone.
- أضيفت اختبارات JSON، رفض البيانات الوصفية غير المعروفة، رفض رابط JAR غير الآمن، ومسار fallback. فحوص C والموارد المحلية ناجحة؛ تجميع Swift وIPA يحتاجان تشغيل GitHub Actions/macOS.
