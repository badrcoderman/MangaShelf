# MangaShelf — بداية مشروع قارئ iPhone مستقل

هذه **مرحلة بناء أولى، وليست IPA جاهزة ولا نسخة مكتملة من Tachimanga**. الاسم مؤقت. الهدف النهائي هو تجربة قريبة جدًا من Tachimanga مع ميزات من منظومة Tachiyomi/Mihon، مع دعم JAR ودون نقل ملفات تنفيذية من العينة المعدّلة.

آخر حالة: سورس 0.3.0 مع تحديث الواجهة واللغة، وفحوص موارد ناجحة. لا توجد IPA جديدة لهذه التعديلات؛ التفاصيل في [تقرير المرحلة الأولى](docs/PHASE-1-UI-AR.md).

## الموجود في المشروع

- تطبيق iOS مكتوب بـ SwiftUI، مع عرض المكتبة بشبكة أغلفة وتصنيفات وبحث وسجل وواجهة قارئ وواجهة إنجليزية افتراضيًا مع العربية خيارًا محفوظًا.
- نواة C صغيرة مستقلة لقراءة ZIP/CBZ وGZIP وحقول Protobuf، تعتمد على zlib النظامية.
- طبقة Swift تقرأ فهرس المتجر وحقل `jarUrl` رقم 501، مع قائمة إضافات مضمّنة أو منفصلة وJSON القديم.
- استيراد CBZ/ZIP، قراءة الصفحات والصور، ترتيب طبيعي لأسماء الصفحات، حفظ التقدم والعلامات وحالة القراءة.
- أوضاع صفحات وويب تون، اتجاه يمين/يسار، تكبير، مؤشر الصفحة، إبقاء الشاشة مضاءة، سمات فاتحة وداكنة.
- إضافة التصنيفات وإسناد الكتب إليها وترتيبها وإزالتها، وتغيير أسماء الكتب.
- إزالة الكتب من المكتبة مع الاحتفاظ بالأرشيف في Trash؛ لا تنظيف دائم أو استعادة من الواجهة بعد.
- تصدير بيانات JSON ودمج تقدم الكتب المحلية الموجودة. هذا ليس دعم نسخ Tachimanga/Mihon، ولا يتضمن ملفات الكتب.
- مشروع Xcode فعلي، Swift Package، اختبارات C واختبارات Swift، وسكربتات بناء المحاكي والأرشفة والتصدير.

كتابة تنفيذ الميزة لا تعني أنها اجتازت اختبار iPhone. كل واجهة SwiftUI وطبقة Swift في هذه المرحلة **لم تُترجما أو تُشغّلا هنا** لعدم توفر Swift/Xcode. لا يوجد عرض واجهة مصور على محاكي، ولا ندّعي مطابقة بصرية مكتملة.

## التحقق الذي نُفّذ

نواة C نفسها التي يستخدمها Swift Package اجتازت 34 اختبارًا، تشمل قطع الأرشيف، CRC، التشفير، المسارات، الضغط المفرط، أرقام Protobuf الكبيرة وحقل 501. تشمل الحزمة أيضًا 3,000 حالة عشوائية و1,500 تعديل على أرشيف.

أُجري فحص إضافي بـ AddressSanitizer وUndefinedBehaviorSanitizer على 30,000 مدخل عشوائي و30,000 تعديل مبني على أرشيف اختبار. اكتمل دون تشخيص خطأ من الأداتين. فحص تسرب الذاكرة LeakSanitizer لم يعمل بسبب قيود الوصول إلى `/proc`، ولذلك عُطّل وحده وأُبقي ASan/UBSan.

هذه اختبارات نواة القراءة وليست شهادة خلو من البرمجيات الخبيثة أو تدقيقًا لـ ImageIO أو محرك JVM. النتائج التفصيلية والبصمات في `validation/`.

نجحت كذلك 7 اختبارات Python لفحص ترويسة جهاز ARM64 ورفض المحاكي والترويسات المقطوعة والحزم المفقودة والروابط الرمزية. لا تتضمن هذه الاختبارات تغليف تطبيق iOS حقيقي أو تشغيله.

## تشغيل المشروع على Mac

المطلوب Xcode يدعم iOS 17 وSwift 5.9 أو أحدث. افتح `iOS/MangaShelf.xcodeproj`، واختر مخطط `MangaShelf` ومحاكي iPhone. لا توجد حزم Swift خارجية لتنزيلها؛ `ReaderCore` حزمة محلية.

للاختبارات والبناء دون توقيع:

```bash
bash scripts/build-ios.sh simulator
```

يشغّل السكربت اختبارات Swift أولًا ثم بناء تطبيق المحاكي. إذا فشل أي منهما، يتوقف دون الادعاء بوجود تطبيق ناجح.

لإنتاج IPA غير موقّعة لجهاز ARM64، دون الحاجة لشهادة في خطوة البناء:

```bash
bash scripts/build-ios.sh unsigned
```

يبني في مجلد مؤقت جديد، ويتحقق من بيانات Mach-O ومن أن الحزمة خاصة بجهاز iOS، ثم ينشئ `build/Export/MangaShelf-unsigned.ipa`. تحتاج توقيعًا صالحًا قبل تثبيتها. فحص بنية الحزمة لا يثبت أنها تعمل على الجهاز. هذا المسار **مكتوب ولم يُنفذ على Mac بعد**.

لأرشفة جهاز حقيقي بعد نجاح الاختبارات، اضبط `MANGASHELF_TEAM_ID` و`MANGASHELF_BUNDLE_ID` إلى بيانات فريقك ومعرّف التطبيق الذي تملكه، ثم:

```bash
bash scripts/build-ios.sh archive
```

يلزم توقيع وشهادة وملف provisioning صالحون في بيئة البناء. لا يطلب السكربت إنشاء ملفات توقيع تلقائيًا على حسابك. لتصدير IPA من الأرشيف، اضبط `MANGASHELF_EXPORT_OPTIONS` إلى ملف ExportOptions.plist المناسب والمراجع، ثم:

```bash
bash scripts/build-ios.sh export
```

المخرج المستهدف `build/Export/`. **هذا المسار لم يُنفّذ هنا، ولا يوجد ملف IPA في هذا التسليم.** لم توضع شهادات أو كلمات مرور أو توقيع مزيف في المشروع. يحتاج إصدار التوزيع أيضًا أيقونة تطبيق واختبار خصوصية/توقيع ومراجعة بصرية.

## تجربة القارئ بعد نجاح بناء iOS

يوجد `Tests/ReaderCoreTests/Fixtures/TestComic.cbz` من ثلاث صفحات هندسية أصلية مولدة للاختبار، وليس محتوى مأخوذًا من Tachimanga. انقله إلى Files في المحاكي أو الجهاز، واستورده من زر الإضافة في المكتبة. ترتيب الصفحات المتوقع 1 ثم 2 ثم 10. اختبر الانتقال والتكبير والاتجاه والتمرير وإعادة فتح التطبيق وتقدم القراءة.

لا تُضاف ملفات الاختبار إلى مكتبة المستخدم تلقائيًا، ولا تُضمّن صور مانغا أو مكتبة وهمية في التطبيق.

## حدود المرحلة الحالية

1. **JAR:** عرض الفهرس فقط. لا JVM مضمّن ولا تنزيل أو تثبيت أو تشغيل إضافات. لا حاجة لتفعيل الثقة الآن لأن الكود لا ينفّذ الحزم أصلًا. سياسة الثقة والتوقيع مطلوبة قبل إضافة التشغيل.
2. **الفهرس:** معالج Protobuf مبني على الحقول التي أمكن توثيقها، ومختبر ببيانات اصطناعية. لم يُختبر رابط Keiyoushi الحي على iPhone. JSON الوصفي و`index_v2` وfallback CDN لم تكتمل.
3. **القراءة:** CBZ/ZIP صور فقط؛ الملفات المشفرة وZIP64 والضغط غير Store/Deflate مرفوضة. حد الملف 256 MiB، الصفحة 32 MiB، الإدخالات 4,096، ومجموع أحجام ZIP المعلنة 1 GiB. دعم الصورة الفعلي يعتمد على ImageIO في النظام.
4. **المكتبة:** ملف JSON ذري صغير بدل قاعدة بيانات SQL. مناسب كبداية، ولم يُختبر بحجم مكتبات إنتاج كبيرة. إزالة كتاب تحفظ ملفه في Trash ولا تستعيد مساحته تلقائيًا.
5. **النسخ:** دمج تقدم كتب لها UUID مطابق على الجهاز نفسه؛ لا استعادة مكتبة الوسائط على جهاز جديد. تصدير metadata قد يتضمن روابط المستودعات المسجلة، لكن الاستيراد لا يعيد تفعيلها تلقائيًا.
6. **الاتصال:** HTTPS فقط، دون كوكيز أو بيانات اعتماد مخزنة، ومع حدود نقل. لا دعم اتصال HTTP محلي بـ Komga أو Kavita بعد.
7. **الميزات المتبقية:** انظر `docs/FEATURES-AR.md`. التشغيل عبر المصادر والتنزيلات والتحديثات والمزامنة والتتبع وEPUB وغيرها لم تُنجز بعد.

## إعادة التحقق محليًا

```bash
python3 scripts/test_native.py
python3 scripts/run_sanitizers.py
python3 scripts/test_packaging.py
python3 scripts/audit_project.py
```

يتطلب فحص C مترجمًا وzlib headers. اختبارات Swift تعمل بواسطة `swift test` في بيئة Swift مناسبة. هذه ليست نسخة من محرك Tachimanga ولا فرعًا من سورايومي؛ كود هذه المرحلة مكتوب للمشروع من جديد.
